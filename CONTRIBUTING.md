# Contributing to Head Up

Thanks for helping. Head Up develops its website, help center, legal texts and design system in the
open; the API and the apps are developed in private repositories.

## Where to start

- **A guide is wrong, unclear or missing a language:** open an issue or a pull request in
  [help](https://github.com/headup-me/help).
- **A question about the privacy policy or the terms:** open an issue in
  [legal](https://github.com/headup-me/legal). Head Up makes every change to the texts itself, so
  pull requests there are not merged.
- **A problem on the website or in the design system:** open an issue in
  [website](https://github.com/headup-me/website) or [design](https://github.com/headup-me/design).
- **A security problem:** follow the [security policy](SECURITY.md), never a public issue.

## Pull requests

- Keep one change per pull request, and say what it changes and why.
- Write commit messages as [Conventional Commits](https://www.conventionalcommits.org/), for example
  `docs(help): explain how to change a username`.
- Sign your commits. The default branch accepts only signed commits, so a pull request with unsigned
  commits cannot be merged.
- The first workflow run of a pull request from outside the organization waits for a maintainer's
  approval.
